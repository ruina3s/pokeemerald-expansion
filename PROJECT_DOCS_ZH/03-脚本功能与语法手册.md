# 03 脚本功能说明与语法手册

> 结论先行：这个项目里的"脚本"有 **5 个完全不同的体系**，混在一起谈会彻底乱。分清这一层，剩下的都是查表：
>
> | # | 体系 | 位置 | 谁执行 | 能干什么 |
> |---|---|---|---|---|
> | 1 | **构建/工具脚本**（Bash、PowerShell、Python） | 根目录、`tools/`、`dev_scripts/`、`migration_scripts/`、`python_tools/` | 你的电脑 / CI | 编译、转换资源、批量改代码 |
> | 2 | **事件脚本**（事件宏，401 个） | `data/maps/*/scripts.inc`、`data/scripts/*.inc` | 游戏内的脚本解释器 | 对话、给道具、战斗、传送、演出、菜单——**做内容的主力** |
> | 3 | **战斗脚本**（战斗宏，424 个） | `data/battle_scripts_1.s` `_2.s` | 战斗引擎的指令表 | 一条招式的结算流程、动画、文字 |
> | 4 | **训练家队伍脚本**（Showdown 语法） | `src/data/trainers.party` | 构建时 `trainerproc` 转成 C | 队伍配置、AI、道具、形态 |
> | 5 | **数据 JSON + 配置宏** | `src/data/*.json`、`include/config/*.h` | 构建时 `jsonproc` / 编译器 | 野生分布、回复点、机制开关 |
>
> 想改"游戏内容"→ 用 2、4、5。想改"招式机制"→ 用 3 + C。想批量处理文件 → 用 1。
> **不要试图用事件脚本做复杂运算**（它没有算术/循环能力），那种需求写 C 的 `special` 函数（见第 8 节）。

## 1.2 `check_history.sh` —— 你一定会遇到的第一个"报错"

你不需要手动执行它：CI 里一跑 `make`，它作为第一个前置检查自动触发。它的完整判断逻辑等价于下面这段伪代码：

```bash
# 伪代码：展示 check_history.sh 的真实行为，不是可直接运行的脚本
if [ -f .histignore ]; then
    exit 0                       # ① 存在 .histignore 标记文件 → 直接放行
fi
if [ -n "$GITHUB_ACTION" ]; then
    exit 0                       # ② 环境变量 GITHUB_ACTION 非空（在 CI 里）→ 放行
fi
if ! git rev-parse --git-dir >/dev/null 2>&1; then
    echo "错误：当前目录不是 git 仓库"   # ③ 找不到 .git → 红字报错
    exit 1                              #    构建直接失败
fi
```

绕过方式（不推荐，但有时必须）：

```bash
touch .histignore     # 在当前目录建一个空文件即可，之后构建不再检查
```

为什么存在：用 "Download ZIP" 而不是 `git clone` 的项目，后续无法 `git pull` 上游更新、无法开分支，官方直接拦下来。

## 1.3 `installdeps.sh` —— 依赖自动安装（本流程不需要它）

```bash
./installdeps.sh      # 只在你"真的想在本机编译"时才用
```

**本项目的约定是全部线上编译**，所以这个脚本你不用跑：CI 的 `Install toolchain` 步骤已经用 `apt-get install` 装好同样的东西（见 `02-GitHub-Actions线上编译.md` 2.2）。它的价值在于：如果你哪天要在临时 Linux 机器上验证，它能一条命令装齐。

真实行为：读 `/etc/os-release` 判断发行版，然后：

| 发行版 | 安装的包 |
|---|---|
| debian / ubuntu | `build-essential libpng-dev gcc-arm-none-eabi binutils-arm-none-eabi libnewlib-arm-none-eabi python3` |
| fedora / centos / rhel | `glibc-devel plocate make clear gcc c++ libpng-devel arm-none-eabi-{gcc,binutils,newlib} python3` |
| arch | `base-devel libpng arm-none-eabi-{gcc,binutils,newlib} python` |
| mingw (MSYS2) | `make mingw-w64-x86_64-toolchain mingw-w64-x86_64-arm-none-eabi-toolchain mingw-w64-x86_64-libpng python3` |

注意：脚本内部用 `$1` 而不是 `$dep` 传包名（原项目的小 bug），装失败时手动 `apt install` 一遍即可。

## 1.5 构建时自动运行的 3 个 Python 脚本（必须知道）

它们由 `Makefile` 的 `generated` 目标调用，`make` 前自动执行：

```make
# 规则：只要 wild_encounters.json 变新，就重新生成 .h
# 左边是目标（生成物），冒号右边是依赖（输入），下一行必须以 TAB 开头
$(DATA_SRC_SUBDIR)/wild_encounters.h: $(DATA_SRC_SUBDIR)/wild_encounters.json
	python3 $(WILD_ENCOUNTERS_TOOL_DIR)/wild_encounters_to_header.py
	# ↑ 读 JSON，写出 C 数组（每张地图的遭遇表）

# 脚本指令表：从 .inc 里的 "指令名, 参数个数" 列表生成 C 枚举
$(INCLUDE_DIRS)/constants/script_commands.h: $(DATA_DIR)/script_cmd_table.inc
	python3 $(MISC_TOOL_DIR)/make_scr_cmd_constants.py

# 可学招式总表：汇总所有 species 能学的招式（教学招式/招式学习器）
```

典型实现（`translate_items.py` 真实逻辑）：

```python
# 1. 读 Excel：第一列是道具的英文名，用它当索引去 C 文件里找对应条目
df = pd.read_excel("python_tools/src/道具.xlsx").set_index('道具')

# 2. 把整个 items.h 读进内存（注意：这是"全量读入 + 全量写回"模式）
content = open("src/data/items.h", encoding="utf-8").read()

# 3. 用正则把每条 [ITEM_XXX] = { .name = ... .description = ... } 里的文本替换掉
#    只替换 .name 和 .description 两个字段，其他数值（价格/威力等）原样保留
new_content = replace_item_info(content, df)

# 4. 直接覆盖写回源文件 —— 所以脚本跑之前必须 commit，否则改错无法回滚
open("src/data/items.h", "w", encoding="utf-8").write(new_content)
```

运行方式：

```bash
pip install pandas openpyxl
git status                       # 确认干净！
python3 python_tools/translate_items.py
git diff --stat                  # 看改了哪些文件
git diff src/data/items.h | head -50
```

产出的 C 片段形态（脚本拼接的实际样子）：

```c
    [ITEM_POTION] =                        // 用道具 ID 当数组下标
    {
        .name = ITEM_NAME("伤药"),          // 显示名：背包、战斗提示、商店都用这个
        .description = COMPOUND_STRING(     // 说明文本：多行字符串拼接，\n 是换行
			"喷雾式伤药。能让\n"
			"宝可梦回复20H\n"
			"P。"),                          // ← 注意：脚本按固定字数硬折行，会把 "HP" 拆成两行
```

⚠️ 三条硬规矩：

1. **必须先 commit**，这些脚本直接写回 `src/data/*.h`，出错不可撤销。
2. 出错会记进 `python_tools/log.txt`（例如"❌ ITEM_XXX 没有单独道具说明，跳过"）。
3. 文本里的换行必须写成 `\n`，并且**每行字数不能超窗口宽度**，否则游戏里会溢出屏幕。

# 第二部分：事件脚本（体系 2）—— 做游戏内容的主力

## 2.1 语法规则（背下来这 8 条就够用）

| 规则 | 说明 |
|---|---|
| `Label::` | **双冒号 = 脚本入口**（全局可见，其他地方能跳过来） |
| `Label:` | 单冒号 = 文本/移动/局部标签（本项目文本全用单冒号） |
| 缩进 | 一条指令一行，行首用 **Tab**（空格会报错） |
| 结束 | 脚本必须以 `end` 结尾（`return` 用于被 `call` 的子过程） |
| 文本结尾 | 字符串必须用 `$` 结束 |
| 换行/翻页 | `\n` 换行、`\p` 翻页、`\l` 滚动一行 |
| 变量占位 | `{PLAYER}` 玩家名、`{KUN}` 男生后缀、`{RIVAL}`、`{STR_VAR_1}` |
| 显示字符 | 必须在 `charmap.txt` 里有映射，否则编译报 "unknown character" |

> **注释怎么写（按文件类型分三种，别混用）**：
>
> | 文件类型 | 注释符号 | 说明 |
> |---|---|---|
> | `.inc` / `.s`（事件脚本、战斗脚本、移动脚本） | `@` | 本项目实际用法；**`#` 不是注释**（`#` 在 preproc 里是预处理指令） |
> | `.c` / `.h` | `//` 或 `/* */` | 标准 C |
> | `.party` | `/* ... */` | **`//` 会报错**，这是 `tools/trainerproc` 的硬限制（文件头第 72 行自己写了 "cannot be used as comments"） |
> | `.json` | **不支持注释** | 加注释会导致 `mapjson`/`jsonproc` 解析失败；说明写在文档里，别写进文件 |

最小可用样例（本仓库真实结构，取自 `data/maps/LittlerootTown/scripts.inc`，已补注释）：

```asm
LittlerootTown_EventScript_Twin::        @ 双冒号 = 全局入口，map.json 的 script 字段填这个名字
	lock                                  @ 冻结：玩家停下、其他 NPC 暂停。每段对话脚本的第一句
	faceplayer                            @ 让本 NPC 转身面向玩家（不加可能背对着你说话）
	goto_if_set FLAG_ADVENTURE_STARTED, LittlerootTown_EventScript_GoodLuck
	                                      @ 旗标"冒险已开始"已置位 → 跳到另一段台词
	goto_if_set FLAG_RESCUED_BIRCH, LittlerootTown_EventScript_YouSavedBirch
	                                      @ "救过博士"已置位 → 又一段不同台词
	goto_if_ne VAR_LITTLEROOT_TOWN_STATE, 0, LittlerootTown_EventScript_GoSaveBirch
	                                      @ 变量不等于 0（剧情已推进）→ 去"救博士"分支
	msgbox LittlerootTown_Text_IfYouGoInGrassPokemonWillJumpOut, MSGBOX_DEFAULT
	                                      @ 上面都不满足时走这段：显示台词，等玩家按 A
	release                               @ 解冻。和 lock 必须成对，漏了就永久卡住
	end                                   @ 脚本结束（必须）

LittlerootTown_Text_IfYouGoInGrassPokemonWillJumpOut:   @ 单冒号 = 文本标签
	.string "呃，呃，呃！\p如果走到野外的草丛里，\n野生的宝可梦可能会跳出来袭击的！$"
	                                      @ \p = 等玩家按键后翻页；\n = 换行；$ = 文本结束符
```

这段同时演示了**三种分支手法**：`goto_if_set`（旗标）、`goto_if_ne`（变量比较）、以及"都满足不了就往下走"的兜底顺序。写剧情时这个模式占 80%。

## 2.2 事件宏全景（401 个，按功能分类）

> 完整机器清单随时可导出（推荐用这个命令核对新版本）：
> ```bash
> grep -oP '(?<=\.macro )[a-zA-Z_0-9]+' asm/macros/event.inc | sort > event_macros.txt
> ```

### A. 流程控制（12）

| 宏 | 作用 |
|---|---|
| `goto Label` | 跳转（不返回） |
| `call Label` / `return` | 调用子脚本 / 返回 |
| `goto_if_eq a, b, Label` | `a == b` 时跳转（还有 `_ne _lt _gt _le _ge`） |
| `goto_if_set FLAG_X, Label` / `goto_if_unset` | 旗标判定跳转 |
| `call_if_eq` / `call_if_set` / `call_if_unset` … | 条件调用（同上一整套） |
| `switch VAR_X` + `case 值, Label` | 多分支分发 |
| `end` | 脚本结束 |
| `delay 帧数` | 等待 N 帧（60 帧 ≈ 1 秒） |
| `waitstate` | 等待异步操作完成（战斗、动画） |
| `trycompare` / `compare` | 比较并写入比较结果 |

### B. 变量与内存（12）

`setvar` `addvar` `subvar` `copyvar` `setorcopyvar` `compare_var_to_value` `compare_var_to_var` `loadword` `loadbyte` `setptr` `setptrbyte` `loadbytefromptr` `copybyte` `copylocal`

> 事件脚本**没有乘除法**。要算就用 `special` 走 C。

### C. 旗标（4）

`setflag` `clearflag` `checkflag` `goto_if_set` / `goto_if_unset`

**分工**：`FLAG_*` 存"有没有发生过"（布尔），`VAR_*` 存"进行到哪一步"（整数状态机）。

### D. 对话与文本（20）

| 宏 | 用途 |
|---|---|
| `msgbox 文本, 类型` | 显示对话框（最常用） |
| `message 文本` / `waitmessage` / `closemessage` | 分步控制（配合 `applymovement` 演出） |
| `messageinstant 文本` | 立即显示不等待 |
| `bufferstring 1, 文本` | 把文本塞进 `{STR_VAR_1}` |
| `bufferspeciesname 1, SPECIES_X` | 宝可梦名 → `{STR_VAR_1}` |
| `buffermovename` / `bufferitemname` / `bufferdecorationname` / `bufferpartymonnick` / `buffertrainername` / `buffertrainerclassname` | 各类名字缓冲 |
| `buffernumberstring 1, 数值` | 数字转字符串 |
| `bufferboxname` / `buffercontestname` / `bufferlivemonnickname` / `bufferleadmonspeciesname` | 其他缓冲 |
| `yesnobox` / `multichoice` / `multichoicedefault` / `multichoicegrid` | 旧式菜单 |
| `signmsg` / `normalmsg` / `textcolor` / `setspeaker` / `loadhelp` / `unloadhelp` | 显示样式 |

`msgbox` 类型（`asm/macros/event.inc` 里定义的常量）：

| 常量 | 值 | 行为 |
|---|---|---|
| `MSGBOX_NPC` | 2 | NPC 对话样式（顶部小框） |
| `MSGBOX_SIGN` | 3 | 告示牌样式 |
| `MSGBOX_DEFAULT` | 4 | 标准对话框 |
| `MSGBOX_YESNO` | 5 | 是/否选择，结果进 `VAR_RESULT`（`YES=1` `NO=0`） |
| `MSGBOX_AUTOCLOSE` | 6 | 自动关闭（战斗后常用） |

## 2.3 实战 demo（照着改就能用）

> 下面每个 demo 都是**可直接粘贴**的完整脚本，`@` 后面是注释。
> 只需要把 `MyTown` 换成你的地图名、把 `FLAG_*`/`VAR_*` 换成你没用过的编号。

### Demo 1：最简 NPC（对话 + 结束）

```asm
MyTown_EventScript_Villager::        @ 入口标签：map.json 的 "script" 字段填这个（不带冒号）
	lock                              @ 冻结玩家 + 所有 NPC，防止对话时被撞走
	faceplayer                        @ NPC 转身面向玩家
	msgbox MyTown_Text_Hello, MSGBOX_DEFAULT
	                                  @ 弹标准对话框；等玩家按 A 关闭后才继续
	release                           @ 解冻（lock 的配对操作，漏掉=玩家卡死）
	end                               @ 脚本结束，交还控制权

MyTown_Text_Hello:                    @ 文本标签，单冒号
	.string "你好！\n今天天气不错。$"  @ \n 换行；$ 必须写在最后
```

`lock` / `release` 是**必须成对**的，漏了 `release` 玩家会被永久卡住。

### Demo 2：一次性给道具（带背包满判定）

```asm
MyTown_EventScript_Gift::
	lock
	faceplayer
	goto_if_set FLAG_RECEIVED_MY_TOWN_GIFT, MyTown_EventScript_GiftDone
	                                  @ 已领过（旗标已置位）→ 跳到"领过了"分支
	giveitem ITEM_POTION, 3           @ 给 3 个伤药。执行后结果写进 VAR_RESULT
	goto_if_eq VAR_RESULT, FALSE, Common_EventScript_ShowBagIsFull
	                                  @ FALSE = 背包满/数量超上限 → 走现成的提示脚本并结束
	setflag FLAG_RECEIVED_MY_TOWN_GIFT @ 记下"已领取"，防止重复刷道具
	msgbox MyTown_Text_GotPotion, MSGBOX_DEFAULT
	release
	end

MyTown_EventScript_GiftDone::         @ 第二个入口：已领过的分支
	msgbox MyTown_Text_AlreadyGot, MSGBOX_DEFAULT
	release
	end

MyTown_Text_GotPotion:
	.string "给你三瓶伤药，路上小心！$"

MyTown_Text_AlreadyGot:
	.string "已经给过你啦。$"
```

要点：`FLAG_*` 防重复、`VAR_RESULT` 判背包、`Common_EventScript_ShowBagIsFull` 是**全局公共脚本**（定义在 `data/event_scripts.s`，所有地图都能直接 `goto` 过去），不用自己写"背包满了"的提示。

### Demo 3：是/否分支

```asm
MyTown_EventScript_Ask::
	lock
	faceplayer
	msgbox MyTown_Text_WantToHeal, MSGBOX_YESNO
	                                  @ MSGBOX_YESNO：出"是/否"框，结果写进 VAR_RESULT
	                                  @ 注意：弹框结束时 VAR_RESULT 已经是 1(YES) 或 0(NO)
	compare VAR_RESULT, YES           @ 显式比较一次（项目习惯写法，方便阅读）
	goto_if_eq MyTown_EventScript_Heal @ 相等 → 跳到治疗分支
	msgbox MyTown_Text_OkayThen, MSGBOX_DEFAULT   @ 选了"否"才执行到这里

	special HealPlayerParty           @ 调用 C 侧函数把队伍治满（data/specials.inc 里注册过）

	end

MyTown_Text_WantToHeal:
	.string "要让宝可梦休息一下吗？$"

MyTown_Text_OkayThen:
	.string "那需要的时候再来。$"

MyTown_Text_AllBetter:

```

### Demo 5：定点传说宝可梦（真实项目写法，摘自 `data/maps/AncientTomb/scripts.inc`）

```asm
MyCave_EventScript_Legend::
	lock
	faceplayer
	waitse                            @ 先等上一声音效播完，避免和叫声重叠
	playmoncry SPECIES_REGISTEEL, CRY_MODE_ENCOUNTER
	                                  @ 播雷吉斯奇鲁的"遭遇"叫声（CRY_MODE_ENCOUNTER 是战斗遭遇音调）
	delay 40                          @ 停 40 帧（≈0.67 秒），制造紧张感
	waitmoncry                        @ 等叫声彻底播完再继续
	setwildbattle SPECIES_REGISTEEL, 40
	                                  @ 登记一场野生战斗：种类 + 等级（可选后 4 项：道具/第二只/等级/道具）
	setflag FLAG_SYS_CTRL_OBJ_DELETE  @ 告诉引擎"这个对象由脚本控制删除"，避免战斗后自动消失
	special StartRegiBattle           @ C 侧函数：真正进入战斗（不同传说有各自的启动函数）
	clearflag FLAG_SYS_CTRL_OBJ_DELETE @ 战斗结束，恢复自动管理
	specialvar VAR_RESULT, GetBattleOutcome
	                                  @ 取战斗结果，写进 VAR_RESULT（胜/败/逃/捕获）
	goto_if_eq VAR_RESULT, B_OUTCOME_WON, MyCave_EventScript_Defeated
	                                  @ 打赢（把它打倒）→ 走"已被击败"分支
	goto_if_eq VAR_RESULT, B_OUTCOME_RAN, MyCave_EventScript_Ran
	                                  @ 逃跑/团灭 → 走"它飞走了"分支，之后还能再遇
	setflag FLAG_DEFEATED_REGISTEEL   @ 剩下的情况 = 捕获成功，记旗标
	release
	end

MyCave_EventScript_Defeated::
	setflag FLAG_DEFEATED_REGISTEEL   @ 打倒了也要记旗标，否则能无限刷
	goto Common_EventScript_RemoveStaticPokemon
	                                  @ 公共脚本：把当前对象从地图上永久移除
	end

MyCave_EventScript_Ran::
	setvar VAR_0x8004, SPECIES_REGISTEEL
	                                  @ 传参：把种类塞进 0x8004，公共脚本会读它
	goto Common_EventScript_LegendaryFlewAway
	                                  @ 公共脚本：播放"飞走了"演出，对象保留（下次还能遇）
	end
```

**这段是"定点神兽"的标准骨架**，四个分支一个都不能少：捕获、打倒、逃跑、重进地图时的旗标判定（`map.json` 里用 `flag` 控制对象是否出现）。

```asm
	switch VAR_RESULT                  @ 玩家选中项的返回值进 VAR_RESULT
	case 0, MyTown_EventScript_Buy
	case 1, MyTown_EventScript_Sell

	end

	end

MyTown_Text_OptionBuy:

MyTown_Text_OptionSell:
	.string "卖$"
MyTown_Text_OptionQuit:
```

优于 `multichoice`：不需要在 `src/data/script_menu.h` 里预定义菜单表，**条数和内容可以在运行时决定**（比如按玩家进度动态增删选项）。

### Demo 9：状态机（一个 VAR 管整条剧情）

```asm
MyTown_EventScript_Story::
	switch VAR_MY_TOWN_STATE          @ 按"剧情进度变量"分发，相当于 C 的 switch
	case 0, MyTown_EventScript_StoryIntro     @ 0 = 还没见过
	case 1, MyTown_EventScript_StoryAfter     @ 1 = 第一次对话完
	case 2, MyTown_EventScript_StoryEnd       @ 2 = 全部结束
	end                                @ 所有 case 都不匹配时的兜底（值被写坏也不会崩）

MyTown_EventScript_StoryIntro::
	msgbox MyTown_Text_Intro, MSGBOX_DEFAULT
	setvar VAR_MY_TOWN_STATE, 1       @ 推进状态：下次对话走 case 1
	release
	end

MyTown_EventScript_StoryAfter::
	msgbox MyTown_Text_After, MSGBOX_DEFAULT
	setvar VAR_MY_TOWN_STATE, 2       @ 推进到终态
	release
	end

MyTown_EventScript_StoryEnd::
	msgbox MyTown_Text_End, MSGBOX_DEFAULT
	release
	end

MyTown_Text_Intro:
	.string "第一次见面。$"
MyTown_Text_After:
	.string "又见面了。$"
MyTown_Text_End:
	.string "之后常来啊。$"
```

配套：在地图 `scripts.inc` 顶部写注释说明每个状态值含义（本项目就是这么干的，见 `LittlerootTown/scripts.inc` 文件头第 7-10 行）：

```asm
	@ State descriptions for VAR_LITTLEROOT_TOWN_STATE
	@ 1: Met Rival
	@ 2: Saving Birch
	@ 3: Received Pokedex
	@ 4: Received Running Shoes
```

> 为什么用 `switch` 而不是一串 `goto_if_eq`：状态一多，`switch` 只查一次变量，且**新增状态只改一行**；`goto_if_eq` 链条则是 O(n) 判断且容易漏分支。

### Demo 10：地图脚本表（进图时自动执行）

```asm
MyTown_MapScripts::                   @ 固定名字：<MapName>_MapScripts，引擎按约定查找
	map_script MAP_SCRIPT_ON_TRANSITION, MyTown_OnTransition
	                                  @ 注册"切换进本图"时调用的函数（淡入前）
	map_script MAP_SCRIPT_ON_RESUME, MyTown_OnResume
	                                  @ 注册"从菜单/战斗返回"时调用的函数
	map_script MAP_SCRIPT_ON_FRAME_TABLE, MyTown_OnFrame
	                                  @ 注册"每帧检查条件"的脚本表
	.byte 0                           @ 表结束标记，必须写

MyTown_OnTransition:                  @ 进图必执行：适合放"根据进度改地图状态"
	setflag FLAG_VISITED_MY_TOWN      @ 示例：记下"来过这里"
	end                               @ 地图脚本也用 end 结束

MyTown_OnResume:                      @ 从菜单/战斗回来时执行
	end                               @ 这里什么都不做，但函数必须存在（否则跳转到空地址）

MyTown_OnFrame:                       @ 帧表：每帧检查下面每一行的条件
	map_script_2 VAR_TEMP_0, 0, MyTown_EventScript_FirstTimeCutscene
	                                  @ 若 VAR_TEMP_0 == 0 → 执行右侧脚本（过场）
	.2byte 0                          @ 表结束标记（16 位 0）
```

可用类型（`include/constants/map_scripts.h`）：`ON_LOAD`(1)、`ON_FRAME_TABLE`(2)、`ON_TRANSITION`(3)、`ON_WARP_INTO_MAP_TABLE`(4)、`ON_RESUME`(5)、`ON_DIVE_WARP`(6)、`ON_RETURN_TO_FIELD`(7)。

对照表：

| `map_script` 类型 | 触发时机 | 典型用途 |
|---|---|---|
| `ON_TRANSITION` | 进入地图、淡入前 | 设置旗标、隐藏/显示 NPC、切音乐 |
| `ON_LOAD` | 地图数据加载 | 改图块（`setmetatile`） |
| `ON_RESUME` | 从菜单/战斗返回 | 恢复状态 |
| `ON_FRAME_TABLE` | 每帧检查变量条件 | 首次进图剧情 |
| `ON_WARP_INTO_MAP_TABLE` | 传送落地瞬间 | 落点朝向/位置 |

> `ON_FRAME_TABLE` 里的脚本执行完必须把条件变量改掉（如 `setvar VAR_TEMP_0, 1`），否则**每一帧都会重跑**，症状是画面卡死或对话无限重复。

### Demo 11：对象事件在 `map.json` 里怎么挂脚本

JSON **不支持注释**（写了 `//` 或 `#` 会让 `mapjson` 解析失败），所以这里给干净 JSON + 逐字段说明：

```json
{
  "local_id": "LOCALID_MY_NPC",
  "graphics_id": "OBJ_EVENT_GFX_SCIENTIST_1",
  "x": 12,
  "y": 8,
  "elevation": 3,
  "movement_type": "MOVEMENT_TYPE_FACE_DOWN",
  "movement_range_x": 0,
  "movement_range_y": 0,
  "trainer_type": "TRAINER_TYPE_NONE",
  "trainer_sight_or_berry_tree_id": "0",
  "script": "MyTown_EventScript_Villager",
  "flag": "FLAG_HIDE_MY_NPC"
}
```

| 字段 | 含义 | 注意 |
|---|---|---|
| `local_id` | 对象在本图内的名字 | 脚本里用 `LOCALID_MY_NPC` 指代它；**改名 = 全项目重命名常量** |
| `graphics_id` | 外观 | 可选值见 `include/constants/event_objects.h` 的 `OBJ_EVENT_GFX_*` |
| `x` / `y` | 地图格坐标 | 左上角为 (0,0) |
| `elevation` | 高度层 | 一般 3（地面）；桥/台阶处不同，填错会"站在墙里" |
| `movement_type` | 待机行为 | `MOVEMENT_TYPE_FACE_DOWN` 原地朝下；`MOVEMENT_TYPE_WANDER_AROUND` 随机游走 |
| `movement_range_x/y` | 游走范围 | 仅 `WANDER_*` 类有意义；0 = 不游走 |
| `trainer_type` | 是否训练家 | `TRAINER_TYPE_NONE` 普通人；`TRAINER_TYPE_NORMAL` 有视野会追上来开战 |
| `trainer_sight_or_berry_tree_id` | 视野半径 / 树果ID | 只有训练家或树果才填，普通人写 `"0"` |
| `script` | 交互时执行的脚本入口 | 填 `::` 定义的那个名字，**不带冒号** |
| `flag` | 隐藏条件旗标 | 该旗标置位时对象消失；`"0"` = 永不隐藏 |

> `LOCALID_MY_NPC` 这个常量**不是你手写的**——`mapjson` 会扫所有 `map.json` 生成 `include/constants/map_event_ids.h`，`local_id` 字段自动变成 `#define LOCALID_MY_NPC n`。所以：**改 `local_id` 名字 = 全项目重命名常量**，改之前先 `grep LOCALID_旧名` 找引用。

## 2.4 事件脚本的能力边界（别硬碰）

| 做不到 | 替代方案 |
|---|---|
| 算术（乘除、取余、位运算） | 写 `special` C 函数 |
| 循环 | 用 `goto` 手工循环；或用 `switch` + 状态机 |
| 字符串拼接/格式化 | `bufferstring` + `buffernumberstring` + `{STR_VAR_x}` |
| 访问任意内存 | `special` 读内存再写进 `VAR` |
| 访问存档之外的数据 | 同上 |
| 读文件/网络 | 根本不存在这个能力 |

## 3.3 战斗脚本 demo（用仓库里真实存在的代码讲解）

以 **`BattleScript_EffectHaze`（黑雾：清除全部能力变化）** 为例，这是 `data/battle_scripts_1.s` 的原文，逐行注释：

```asm
BattleScript_EffectHaze::             @ 双冒号：效果表 src/data/battle_move_effects.h 会引用这个名字
	attackcanceler                     @ 1. 判定招式能否发动（睡眠/畏缩/麻痹/守住…），不能就跳走
	attackanimation                    @ 2. 播招式动画（此时伤害已经在 C 侧算好）
	waitanimation                      @ 3. 等动画播完再继续，否则文字会和动画重叠
	normalisebuffs                     @ 4. 把双方所有能力等级归零 —— 这一条才是"黑雾"的真正效果
	printstring STRINGID_STATCHANGESGONE   @ 5. 印"能力变化消失了"（字符串 ID 在 battle_string_ids.h）
	waitmessage B_WAIT_TIME_LONG       @ 6. 等玩家看完（LONG ≈ 按下 A 或超时）
	goto BattleScript_MoveEnd          @ 7. 走统一收尾：moveendall（清回合状态）+ end
```

再看 **普通攻击招式**（`BattleScript_EffectHit`），你会发现它短得反直觉：

```asm
BattleScript_EffectHit::              @ 绝大多数"造成伤害"的招式共用这一段
	attackcanceler                     @ 判定能否发动
	critmessage                        @ 印"击中要害！"（是否要害已由 C 侧决定）
	waitmessage B_WAIT_TIME_LONG
	resultmessage                      @ 印"效果拔群/效果不好"（倍率也由 C 侧算好）
	waitmessage B_WAIT_TIME_LONG
	setadditionaleffects               @ 挂上 moves_info.h 里配的追加效果（灼伤/降能力…）
BattleScript_MoveEnd::                @ 所有招式共用的收尾入口
	moveendall                         @ 清回合内临时状态、触发回合结束事件
	end                                @ 战斗脚本结束
```

原因：伤害/命中/暴击在 C 侧已经算完并写进 `gBattleMoveDamage` 等全局变量，脚本只负责"把结果念出来 + 挂追加效果"。**这就是为什么改招式手感要去 `src/battle_util.c`，而不是改脚本。**

自定义一个效果的完整 demo（假设要做"命中后强制换人"），每行都写了注释：

```asm
BattleScript_MyForceSwitch::
	attackcanceler                     @ 招式能否发动
	attackstring                       @ 印"XX 使用了 YY！"
	ppreduce                           @ 扣 PP（不写这句，招式就是无限 PP）
	typecalc                           @ 计算属性一致/克制倍率（C 侧）
	attackanimation                    @ 播招式动画
	waitanimation
	effectivenesssound                 @ 播"效果拔群/不佳"音效
	hitanimation BS_TARGET             @ 目标受击闪烁（BS_TARGET = 目标方，另有 BS_ATTACKER）
	waitstate                          @ 等受击动画结束
	healthbarupdate BS_TARGET          @ 更新血条显示
	datahpupdate BS_TARGET, ASSURANCE_DOUBLE
	                                  @ 真正扣血；第二个参数是"至少扣多少"的保底策略
	critmessage                        @ 印会心一击（如有）
	waitmessage B_WAIT_TIME_LONG
	resultmessage                      @ 印效果拔群/不佳
	waitmessage B_WAIT_TIME_LONG
	tryfaintmon BS_TARGET              @ 判定目标是否濒死并播倒下动画
	call BattleScript_MyForceSwitch_Effect   @ 调用自己的追加逻辑（call 会返回）
	goto BattleScript_MoveEnd          @ 回统一收尾

BattleScript_MyForceSwitch_Effect:     @ 子过程：单冒号即可，用 call 进入、return 退出
	printstring STRINGID_EMPTYSTRING3  @ 先清一下文字缓冲，避免上一句残留
	waitmessage B_WAIT_TIME_LONG
	forcerandomswitch                  @ 强制把目标换下场（随机换一只）
	return                             @ 返回调用点
```

> 上面这段是"可以照着改"的模板：所有宏名都来自本项目真实的 `asm/macros/battle_script.inc`。写之前建议先 `grep` 一个功能相似的现有脚本抄结构。
> **顺序不能随意调**：`ppreduce` 在 `attackstring` 之后、`typecalc` 之前；`datahpupdate` 必须在 `healthbarupdate` 之后。顺序错了会出现"血条不动但实际掉血"这类怪象。

新增一条完全自定义的招式效果，需要同时动 5 个地方：

1. `include/constants/battle_move_effects.h` → 加 `EFFECT_MY_EFFECT`
2. `src/data/battle_move_effects.h` → 加 `[EFFECT_MY_EFFECT] = { .battleScript = BattleScript_MyEffect }`
3. `data/battle_scripts_1.s` → 写 `BattleScript_MyEffect: …`
4. `src/data/moves_info.h` → 目标招式的 `.effect = EFFECT_MY_EFFECT`
5. `include/constants/battle_string_ids.h` + `src/data/battle_message.c` → 如果要新文字

> ⚠️ 三个必须遵守的格式约束（`tools/trainerproc` 的硬要求，错了直接编不过）：
> 1. **训练家与第一只宝可梦之间、宝可梦与宝可梦之间必须有空行**。
> 2. **注释只能用 `/* ... */`**，`//` 不是注释（文件头第 72 行原话："cannot be used as comments"）。
> 3. **招式（`- 招式名`）必须是该宝可梦的最后几行**，后面不能再出现 `Level:` 之类字段。

# 第五部分：数据 JSON（体系 5）

## 5.1 野生分布 `src/data/wild_encounters.json`

结构：分组定义"遭遇槽位" → 每张地图填 12 个陆地槽 / 5 个水面槽 / 5 个碎岩槽。

JSON 不支持注释，下面是**最小可用结构**（已精简），字段含义见后面表格：

```json
{
  "wild_encounter_groups": [
    {
      "label": "gWildMonHeaders",
      "for_maps": true,
      "fields": [
        { "type": "land_mons", "encounter_rates": [20,20,10,10,10,10,5,5,4,4,1,1] },
        { "type": "water_mons", "encounter_rates": [60,30,5,4,1] },
        { "type": "rock_smash_mons", "encounter_rates": [60,30,5,4,1] },
        { "type": "fishing_mons", "encounter_rates": [70,30,60,20,40,40,4,1,4,1] }
      ],
      "encounters": [
        {
          "map": "MAP_ROUTE101",
          "base_label": "gRoute101LandMons",
          "land_mons": {
            "mons": [
              ["SPECIES_WURMPLE", 2, 2],
              ["SPECIES_ZIGZAGOON", 3, 4]
            ]
          }
        }
      ]
    }
  ]
}
```

| 字段 | 含义 | 坑 |
|---|---|---|
| `label` | 生成到 C 里的总表名 | 改名要同步 `src/data/wild_encounters.h` 的引用 |
| `for_maps` | `true` = 按地图自动展开；`false` = 手动指定 | 本项目全用 `true` |
| `fields[].encounter_rates` | 每个槽位的出现概率（**必须合计 100**） | 陆地 12 槽固定；水面/碎岩 5 槽；钓鱼 10 槽 |
| `map` | 地图常量 `MAP_*` | 必须已在 `map_groups.json` 注册 |
| `base_label` | 该地图这张表的 C 符号名前缀 | 全项目唯一 |
| `mons` | `[种类, 最低等级, 最高等级]` 三元组数组 | **条数必须等于槽位数**，少一条会编译失败或概率错位 |

> 注意：本项目里这张表**体量巨大**（几千行），实际编辑建议用 Porymap 的野生分布编辑器，或者写脚本批量改。
> 编辑时**不要整体重排缩进**——diff 会炸成几千行，PR 没法看。

改完 push：CI 里 `wild_encounters_to_header.py` 会重新生成 `src/data/wild_encounters.h`，然后编译。

## 5.2 `jsonproc` 的模板机制

`json_data_rules.mk` 里的关系：

```
src/data/wild_encounters.json  +  src/data/wild_encounters.constants.json.txt
        └──────────── jsonproc (Inja 模板) ────────────┘
                            ↓
              include/constants/wild_encounter.h
```

模板语法（Inja，语法接近 Jinja2）核心四条：

```
{% for e in encounters %}       循环开始：遍历 encounters 数组
  {% if e.map %}                条件开始：字段存在才输出
  {{ e.map }}                   输出变量值（相当于 printf）
  {% endif %}                   条件结束
{% endfor %}                    循环结束

{# 这是 Inja 的注释，不会输出到生成文件里 #}
```

> 这些 `.txt` 模板就是 **`jsonproc` 的输入**：它把 JSON 数据 + 模板合成 C 头文件。所以改数据结构时要**同时**改 JSON 和模板，只改一边会生成出奇怪的东西或直接报错。

## 5.3 回复点 `src/data/heal_locations.json`

`setrespawn` 要用到的常量来源。加新城镇的回复点：JSON 里加一条 → push → CI 编译 → `HEAL_LOCATION_XXX` 常量自动可用。

```json
{
  "id": "HEAL_LOCATION_MY_TOWN",
  "map": "MAP_MY_TOWN",
  "x": 10,
  "y": 8
}
```

| 字段 | 含义 |
|---|---|
| `id` | 生成的常量名，脚本里 `setrespawn HEAL_LOCATION_MY_TOWN` |

# 第六部分：配置宏（体系 5 的另一半，最省力的"脚本"）

改一行 `#define` = 改一条游戏机制，不用写逻辑。

```c
// ===== include/config/battle.h：战斗相关 =====
#define B_EXP_CATCH GEN_LATEST        // 捕获宝可梦是否给经验：GEN_LATEST=给(Gen6+)，GEN_3=不给
#define B_CRIT_CHANCE GEN_LATEST      // 暴击率公式：GEN_LATEST=当前代，GEN_3=老公式(1/16)
#define B_MEGA_EVO TRUE               // 是否启用 Mega 进化：TRUE=启用，FALSE=整系统关闭
#define B_DYNAMAX TRUE                // 是否启用极巨化
#define B_TERASTALLIZATION TRUE       // 是否启用太晶化
#define B_X_ITEMS_BUFF GEN_LATEST     // 强化道具效果：GEN_LATEST=提升2级(Gen7+)，GEN_3=提升1级

// ===== include/config/pokemon.h：宝可梦本体 =====
#define P_UPDATED_STATS GEN_LATEST    // 种族值用哪一代：GEN_LATEST=最新，GEN_3=第三代原始值
#define P_EGG_HATCH_LEVEL GEN_LATEST  // 孵出的蛋几级：GEN_LATEST=1级(Gen4+)，GEN_3=5级
#define P_LEGENDARY_PERFECT_IVS GEN_LATEST  // 传说宝可梦是否保底 3V

// ===== include/config/general.h：全局基准 =====
#define GEN_LATEST GEN_9              // "最新代"到底指哪一代：所有 GEN_LATEST 都跟着它走
#define UNITS UNITS_METRIC            // 单位制：METRIC=米/千克，IMPERIAL=英尺/磅
```

**三种取值写法**（每个 `B_*` / `P_*` 都适用）：

| 写法 | 含义 | 例 |
|---|---|---|
| `GEN_LATEST` | 跟随 `general.h` 的 `GEN_LATEST`（当前 = Gen9） | 想整体保持最新手感 |
| `GEN_3` / `GEN_4` … `GEN_9` | 锁定到某一代的行为 | 单点回退某条机制 |
| `TRUE` / `FALSE` | 纯开关型配置 | `B_MEGA_EVO` |

**一把梭改成"纯第三代手感"**：把 `include/config/pokemon.h` 里所有 `P_*` 从 `GEN_LATEST` 改成 `GEN_3`，`include/config/battle.h` 里所有 `B_*` 同理。

> ⚠️ 改完必须走**全量构建**（Actions 手动触发时勾 `clean_build`）。配置宏被几百个 `.c` 包含，增量判断容易漏掉跨文件影响，症状是"改了宏但游戏行为没变"。

# 第七部分：C 侧 `special` 函数（补齐脚本的能力缺口）

## 7.1 注册方式（三步，最后一步最容易忘）

```asm
@ 步骤 1）在 data/specials.inc 里注册，让脚本层能按名字找到这个 C 函数
@ 宏原型：def_special ptr, requests_effects=0, waitstate=0
@   ptr               = C 函数名（必须与实现完全一致）
@   requests_effects  = 1 时表示这个 special 会触发"特殊效果"(见 include/constants/specials.h)
@   waitstate         = 1 时脚本会自动等它完成，不需要额外 waitstate
def_special MyCustomFunction
```

```c
// 步骤 2）在某个头文件里声明（例：include/script_pokemon_util.h）
// 声明必须放在 include/ 下，且被实现文件 include，否则编译期看不到原型
void MyCustomFunction(void);
```

```c
// 步骤 3）在任意 src/*.c 里实现
void MyCustomFunction(void)
{
    // gSpecialVar_Result 就是脚本里的 VAR_RESULT：写它 = 把返回值交给脚本
    gSpecialVar_Result = CalculateSomething();
}
```

> 漏掉**步骤 2** 的典型症状：链接期报 `undefined reference to 'MyCustomFunction'`，但你在 `src/` 里明明写了实现——因为 `data/specials.inc` 生成的汇编需要一个可见的全局符号。

## 7.2 脚本里调用

```asm
	special MyCustomFunction                 @ 不需要返回值时用这个（返回值被丢弃）
	specialvar VAR_RESULT, MyCustomFunction  @ 需要返回值时用这个，结果进 VAR_RESULT
	                                          @ 注意：第二个参数是变量名，函数名放后面
```

真实例子（本项目）：`data/specials.inc` 里 `def_special HealPlayerParty`，脚本里写 `special HealPlayerParty` 就把队伍治满。

## 7.3 需要传参怎么办

事件脚本没有函数参数概念，**传参靠 `VAR_0x8000` ~ `VAR_0x800D` 这 14 个约定变量**：

```asm
@ 脚本侧：把参数塞进约定的变量，再调用
	setvar VAR_0x8004, SPECIES_REGISTEEL   @ 第 1 个参数 → VAR_0x8004
	setvar VAR_0x8005, 40                  @ 第 2 个参数 → VAR_0x8005（如果有）
	special GetSpeciesSomething             @ 调用；函数内部去读这两个变量
```

```c
// C 侧：用 gSpecialVar_0x8004..0x800D 接收，用 gSpecialVar_Result 回传
void GetSpeciesSomething(void)
{
    u16 species = gSpecialVar_0x8004;   // 接第 1 个参数
    gSpecialVar_Result = species * 2;   // 回传结果，脚本里读 VAR_RESULT
}
```

> 这套 `0x8000` 系列变量是**全局共享**的，任何 special 都可能改写它们。所以：**设完参数要马上调用**，中间不要插入别的 `special` 或 `msgbox`（某些 msgbox 也会用到这批变量）。
