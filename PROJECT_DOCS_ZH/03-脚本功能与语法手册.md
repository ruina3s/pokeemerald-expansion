# 03 脚本功能说明与语法手册

> 结论先行：这个项目里的"脚本"有 **5 个完全不同的体系**，混在一起谈会彻底乱。分清这一层，剩下的都是查表：
>
> | # | 体系 | 位置 | 谁执行 | 能干什么 |
> |---|---|---|---|---|
> | 1 | **构建/工具脚本**（Bash、PowerShell、Python） | 根目录、`tools/`、`dev_scripts/`、`migration_scripts/`、`python_tools/` | 你的电脑 / CI | 编译、转换资源、批量改代码 |
> | 2 | **事件脚本**（事件宏，401 个） | `data/maps/*/scripts.inc`、`data/scripts/*.inc` | 游戏内的脚本解释器 | 对话、给道具、战斗、传送、演出、菜单——**做内容的主力** |
> | 3 | **战斗脚本**（战斗宏，424 个） | `data/battle_scripts_1.s` `_2.s` | 战斗引擎的指令表 | 一条招式的结算流程、动画、文字 |
> | 4 | **训练家队伍脚本**（Showdown 语法） | `src/data/trainers.party` | 构建时 `trainerproc` 转成 C | 队伍配置、AI、道具、形态 |
> | 5 | **数据 JSON + 配置宏** | `src/data/*.json`、`include/config/*.h` | 构建时 `jsonproc` / 编译器 | 野生分布、回复点、机制开关 |
>
> 想改"游戏内容"→ 用 2、4、5。想改"招式机制"→ 用 3 + C。想批量处理文件 → 用 1。
> **不要试图用事件脚本做复杂运算**（它没有算术/循环能力），那种需求写 C 的 `special` 函数（见第 8 节）。

## 1.2 `check_history.sh` —— 你一定会遇到的第一个"报错"

```bash
make            # 首次编译时它会先跑
```

行为逻辑（真实实现）：

- 存在 `.histignore` 文件 → 直接放行
- 环境变量 `GITHUB_ACTION` 非空 → 放行（CI 里跳过）
- 找不到 `git` 或当前目录不是 git 仓库 → **红字报错并 `exit 1`**

绕过方式（不推荐，但有时必须）：

```bash
touch .histignore
```

为什么存在：用 "Download ZIP" 而不是 `git clone` 的项目，后续无法 `git pull` 上游更新、无法开分支，官方直接拦下来。

## 1.3 `installdeps.sh` —— 依赖自动安装

```bash
./installdeps.sh
```

真实行为：读 `/etc/os-release` 判断发行版，然后：

| 发行版 | 安装的包 |
|---|---|
| debian / ubuntu | `build-essential libpng-dev gcc-arm-none-eabi binutils-arm-none-eabi libnewlib-arm-none-eabi python3` |
| fedora / centos / rhel | `glibc-devel plocate make clear gcc c++ libpng-devel arm-none-eabi-{gcc,binutils,newlib} python3` |
| arch | `base-devel libpng arm-none-eabi-{gcc,binutils,newlib} python` |
| mingw (MSYS2) | `make mingw-w64-x86_64-toolchain mingw-w64-x86_64-arm-none-eabi-toolchain mingw-w64-x86_64-libpng python3` |

注意：脚本内部用 `$1` 而不是 `$dep` 传包名（原项目的小 bug），装失败时手动 `apt install` 一遍即可。

## 1.4 `asmdiff.sh` / `asmdiff.ps1` —— 老实说：对你没用

```bash
# 比较 ROM 中 0x08000000 起 0x100 字节的反汇编
./asmdiff.sh 0x8000000 0x100
```

```powershell
# Windows：需要 DEVKITARM 环境变量，且根目录有 baserom.gba 和 pokeemerald.gba
.\asmdiff.ps1 08000000 100 -DiffTool 'code --diff'
```

**为什么说你用不上**：这是 pret 反编译项目"逐函数匹配原版 ROM"的调试工具。pokeemerald-expansion 1.9 之后已彻底抛弃 agbcc 匹配路线（`make agbcc` 直接报错退出），你也没有 `baserom.gba`。**除非你在做 pret 上游的匹配工作，否则忽略这两个脚本。**

## 1.5 构建时自动运行的 3 个 Python 脚本（必须知道）

**铁律**：


典型实现（`translate_items.py` 真实逻辑）：

```python
df = pd.read_excel("python_tools/src/道具.xlsx").set_index('道具')
content = open("src/data/items.h", encoding="utf-8").read()

```

运行方式：

```bash

python3 python_tools/translate_items.py
git diff --stat                  # 看改了哪些文件
git diff src/data/items.h | head -50
```

产出的 C 片段形态（脚本拼接的实际样子）：

```c
    [ITEM_POTION] =
    {
        .name = ITEM_NAME("伤药"),
        .description = COMPOUND_STRING(
			"喷雾式伤药。能让\n"
			"宝可梦回复20H\n"
			"P。"),
```

⚠️ 三条硬规矩：

1. **必须先 commit**，这些脚本直接写回 `src/data/*.h`，出错不可撤销。
2. 出错会记进 `python_tools/log.txt`（例如"❌ ITEM_XXX 没有单独道具说明，跳过"）。
3. 文本里的换行必须写成 `\n`，并且**每行字数不能超窗口宽度**，否则游戏里会溢出屏幕。

# 第二部分：事件脚本（体系 2）—— 做游戏内容的主力

## 2.1 语法规则（背下来这 8 条就够用）

| 规则 | 说明 |
|---|---|
| `Label::` | **双冒号 = 脚本入口**（全局可见，其他地方能跳过来） |
| `Label:` | 单冒号 = 文本/移动/局部标签（本项目文本全用单冒号） |
| 缩进 | 一条指令一行，行首用 **Tab**（空格会报错） |
| 结束 | 脚本必须以 `end` 结尾（`return` 用于被 `call` 的子过程） |
| 文本结尾 | 字符串必须用 `$` 结束 |
| 换行/翻页 | `\n` 换行、`\p` 翻页、`\l` 滚动一行 |
| 变量占位 | `{PLAYER}` 玩家名、`{KUN}` 男生后缀、`{RIVAL}`、`{STR_VAR_1}` |
| 显示字符 | 必须在 `charmap.txt` 里有映射，否则编译报 "unknown character" |

最小可用样例（本仓库真实结构，取自 `data/maps/LittlerootTown/scripts.inc`）：

```asm
LittlerootTown_EventScript_Twin::
	lock
	faceplayer
	goto_if_set FLAG_ADVENTURE_STARTED, LittlerootTown_EventScript_GoodLuck
	msgbox LittlerootTown_Text_IfYouGoInGrassPokemonWillJumpOut, MSGBOX_DEFAULT
	release
	end

LittlerootTown_Text_IfYouGoInGrassPokemonWillJumpOut:
	.string "草丛里会有宝可梦跳出来哦！$"
```

## 2.2 事件宏全景（401 个，按功能分类）

> 完整机器清单随时可导出（推荐用这个命令核对新版本）：
> ```bash
> grep -oP '(?<=\.macro )[a-zA-Z_0-9]+' asm/macros/event.inc | sort > event_macros.txt
> ```

### A. 流程控制（12）

| 宏 | 作用 |
|---|---|
| `goto Label` | 跳转（不返回） |
| `call Label` / `return` | 调用子脚本 / 返回 |
| `goto_if_eq a, b, Label` | `a == b` 时跳转（还有 `_ne _lt _gt _le _ge`） |
| `goto_if_set FLAG_X, Label` / `goto_if_unset` | 旗标判定跳转 |
| `call_if_eq` / `call_if_set` / `call_if_unset` … | 条件调用（同上一整套） |
| `switch VAR_X` + `case 值, Label` | 多分支分发 |
| `end` | 脚本结束 |
| `delay 帧数` | 等待 N 帧（60 帧 ≈ 1 秒） |
| `waitstate` | 等待异步操作完成（战斗、动画） |
| `trycompare` / `compare` | 比较并写入比较结果 |

### B. 变量与内存（12）

`setvar` `addvar` `subvar` `copyvar` `setorcopyvar` `compare_var_to_value` `compare_var_to_var` `loadword` `loadbyte` `setptr` `setptrbyte` `loadbytefromptr` `copybyte` `copylocal`

> 事件脚本**没有乘除法**。要算就用 `special` 走 C。

### C. 旗标（4）

`setflag` `clearflag` `checkflag` `goto_if_set` / `goto_if_unset`

**分工**：`FLAG_*` 存"有没有发生过"（布尔），`VAR_*` 存"进行到哪一步"（整数状态机）。

### D. 对话与文本（20）

| 宏 | 用途 |
|---|---|
| `msgbox 文本, 类型` | 显示对话框（最常用） |

| `messageinstant 文本` | 立即显示不等待 |

### Demo 11：对象事件在 `map.json` 里怎么挂脚本

```json
{
  "local_id": "LOCALID_MY_NPC",
  "graphics_id": "OBJ_EVENT_GFX_SCIENTIST_1",
  "x": 12, "y": 8, "elevation": 3,
  "movement_type": "MOVEMENT_TYPE_FACE_DOWN",
  "trainer_type": "TRAINER_TYPE_NONE",
  "script": "MyTown_EventScript_Villager",
  "flag": "FLAG_HIDE_MY_NPC"
}
```

- `local_id`：脚本里用 `LOCALID_MY_NPC` 指代它
- `flag`：设了旗标就隐藏（`0` 表示永不隐藏）
- `trainer_type`：`TRAINER_TYPE_NORMAL` = 有视野会追击（搭配 `trainer_sight_or_berry_tree_id` 设视野半径）

> `LOCALID_MY_NPC` 这个常量**不是你手写的**——`mapjson` 会扫所有 `map.json` 生成 `include/constants/map_event_ids.h`，`local_id` 字段自动变成 `#define LOCALID_MY_NPC n`。所以：**改 `local_id` 名字 = 全项目重命名常量**，改之前先 `grep LOCALID_旧名` 找引用。

## 2.4 事件脚本的能力边界（别硬碰）

| 做不到 | 替代方案 |
|---|---|
| 算术（乘除、取余、位运算） | 写 `special` C 函数 |
| 循环 | 用 `goto` 手工循环；或用 `switch` + 状态机 |
| 字符串拼接/格式化 | `bufferstring` + `buffernumberstring` + `{STR_VAR_x}` |
| 访问任意内存 | `special` 读内存再写进 `VAR` |
| 访问存档之外的数据 | 同上 |
| 读文件/网络 | 根本不存在这个能力 |

以 **`BattleScript_EffectHaze`（黑雾：清除全部能力变化）** 为例，这是 `data/battle_scripts_1.s` 的原文：

```asm
BattleScript_EffectHaze::
	attackcanceler              @ 1. 先判定招式是否被打断（睡眠/畏缩/守住…）
	attackanimation             @ 2. 播招式动画
```

```asm
BattleScript_EffectHit::
	attackcanceler
	critmessage
	waitmessage B_WAIT_TIME_LONG

	waitmessage B_WAIT_TIME_LONG
	setadditionaleffects

	moveendall
	end
```

# 第六部分：配置宏（体系 5 的另一半，最省力的"脚本"）

改一行 `#define` = 改一条游戏机制，不用写逻辑。

```c
// include/config/battle.h
#define B_EXP_CATCH GEN_LATEST        // 捕获也获得经验（Gen6+ 行为）
#define B_CRIT_CHANCE GEN_LATEST      // 暴击率按最新代
#define B_MEGA_EVO TRUE               // 开 Mega 进化
#define B_DYNAMAX TRUE                // 开极巨化
#define B_TERASTALLIZATION TRUE       // 开太晶化

// include/config/pokemon.h
#define P_UPDATED_STATS GEN_LATEST    // 种族值用最新代
#define P_EGG_HATCH_LEVEL GEN_LATEST  // 蛋孵出 1 级（Gen4+）

// include/config/general.h
#define GEN_LATEST GEN_9              // 全局代际基准
#define UNITS UNITS_METRIC            // 公制单位
```

**一把梭改成"纯第三代手感"**：把 `include/config/pokemon.h` 里所有 `P_*` 从 `GEN_LATEST` 改成 `GEN_3`，`include/config/battle.h` 里所有 `B_*` 同理。改完必须 `make clean && make`（配置宏影响几乎所有编译单元，增量编译可能不彻底）。

# 第七部分：C 侧 `special` 函数（补齐脚本的能力缺口）

## 7.1 注册方式（两步）

```asm
@ 1) data/specials.inc 里注册
def_special MyCustomFunction
```

```c
// 2) 在任意 src/*.c 里实现（需在 include/ 里有声明）
void MyCustomFunction(void)
{
    // 读/写 gSpecialVar_Result 就是脚本里的 VAR_RESULT
    gSpecialVar_Result = CalculateSomething();
}
```

## 7.2 脚本里调用

```asm
	special MyCustomFunction              @ 不返回值的
	specialvar VAR_RESULT, MyCustomFunction  @ 要取返回值的
```

真实例子（本项目）：`data/specials.inc:20: def_special HealPlayerParty`，脚本里 `special HealPlayerParty` 就把队伍治满。

## 7.3 需要传参怎么办

事件脚本传参靠 `VAR_0x8000` ~ `VAR_0x800D`：

```asm
	setvar VAR_0x8004, SPECIES_REGISTEEL
	special GetSpeciesSomething
```

```c
void GetSpeciesSomething(void)
{
    u16 species = gSpecialVar_0x8004;   // 接参数
    gSpecialVar_Result = species * 2;   // 回传
}
```
