# 04 修改项目的基本流程（软件 · 目录 · 连锁处理）

> 结论先行：改这个项目只有 **5 个层级**，先定层级再动手，否则改完不知道为什么要动 8 个文件。
>
> | 层级 | 改什么 | 目录 | 需要软件 | 改完做什么 |
> |---|---|---|---|---|
> | ① 配置 | 游戏机制开关（代际、极巨化、孵蛋规则…） | `include/config/*.h` | VS Code | `make clean && make`（全量重编） |
> | ② 数据 | 招式数值、道具、种族、队伍、野生分布 | `src/data/**`、`include/constants/**` | VS Code | `make` |
> | ③ 脚本 | 对话、剧情、NPC、商店、战斗编排 | `data/maps/*/scripts.inc`、`data/scripts/*.inc`、`data/battle_scripts_1.s` | VS Code（或 Porymap 编辑地图/对象） | `make` + 游戏内实测 |
> | ④ 资源 | 图片、音乐、图块 | `graphics/**`、`sound/**` | Aseprite / MIDI 编辑器 | `make`（会自动重转格式） |
> | ⑤ 引擎 | 逻辑实现（新机制、AI、菜单） | `src/*.c`、`include/*.h` | VS Code | `make` + `make check` |
>
> **铁律 5 条**：
> 1. 改动前先 `git checkout -b feature/xxx`，别在 `master` 上裸改。
> 2. 生成文件（`*.4bpp`、`*.lz`、`src/data/trainers.h`、`include/constants/map_groups.h` 等）**永远不要手改**，改输入。
> 3. 编译不过 ≠ 环境问题，先看第一行 error，`-Werror` 会把警告当错误。
> 4. 删除比新增危险 10 倍：先删引用，再删定义。
> 5. 每次提交前 `git status` 确认没带进 `build/` 和 `.gba`。

## 1. 软件清单（Windows 环境）

| 用途 | 推荐软件 | 说明 / 坑 |
|---|---|---|
| 编译环境 | **WSL2 + Ubuntu** | **必须**。Windows 原生（MSYS2）能编但慢 10–20 倍；Cygwin 更慢且上游已标注损坏 |
| 代码编辑 | **VS Code** | 装 C/C++ 扩展 + EditorConfig；本项目 `.editorconfig` 缩进为 **Tab** |
| 版本控制 | Git（Git for Windows 自带 Git Bash） | 你当前就是这套 |
| 地图编辑 | **Porymap** | 读写 `data/maps/*/map.json` 与 `data/layouts/`；**注意**：expansion 独有字段（`region`、`requires_flash` 等）旧版 Porymap 可能不识别，保存后必须 `git diff` 复核 |
| 图块/图集 | Porymap 内置 tilemap 编辑器 + Aseprite | 图块必须索引色 |
| 像素图 | **Aseprite**（付费）/ GraphicsGale / LibreSprite（免费） | 输出必须是**索引色 PNG，≤16 色** |
| 音乐 | Anvil Studio / FL Studio / LMMS | 导出 `.mid`，再在 `sound/songs/midi/midi.cfg` 登记 |
| 运行测试 | **mGBA** | 支持 `.sym` 符号，可断点调试 |
| 二进制对比 | HxD / 010 Editor | 改 `.bin`/`.gbapal` 时用 |
| 汉化文本 | Excel + Python（pandas / openpyxl） | `python_tools/` 那套 |
| JSON 校验 | VS Code 内置（JSON schema 提示） | `map.json` 少个逗号就编不过 |

**不要用的**：Word / WPS 改 `.inc`/`.h`（会引入全角标点、BOM）；在线 JSON 美化器重排整个 `wild_encounters.json`（diff 会爆炸）。

> 关于 **Poryscript**（`.pory` 脚本语言）：本项目**没有**内置支持，也没有任何 `.pory` 文件。想用需要自己往 Makefile 加规则，属于"给自己挖坑"，不建议。

## 3. 标准工作流（7 步）

```bash
# 0) 确保工作区干净
git status
git pull origin master

# 1) 开分支（命名建议：feature/xxx、fix/xxx、content/xxx）
git checkout -b feature/my-new-npc

# 2) 改文件（见第 4 节场景手册）
#    ——VS Code 改 .inc/.h/.json；Porymap 改地图；Aseprite 改图

# 3) 编译
make -j"$(nproc)" -O all

# 4) 测试（机制/战斗类改动必须跑）
make -j"$(nproc)" check

# 5) 实机验证（mGBA 打开 pokeemerald.gba，用 Quickstart 直接进游戏）
#    include/config/quickstart.h 里 ENABLE_QUICKSTART = TRUE → 标题画面按 SELECT 秒进新游戏

# 6) 提交（看清楚改了什么）
git status
git diff --stat
git add -A
git commit -m "content: add gift NPC in LittlerootTown"

# 7) 推送 + PR
git push -u origin feature/my-new-npc
```

**Quickstart 是开发期神器**：不用每次重开存档跑开场剧情。改完逻辑 → `make` → 标题按 SELECT → 30 秒内到测试点。

## 4. 场景操作手册（12 个高频改动）

### 场景 1：改一句对话

| 项 | 内容 |
|---|---|
| 改哪里 | `data/maps/<Map>/scripts.inc` 末尾的 `Xxx_Text_Yyy:` 段 |
| 软件 | VS Code（或 Porymap 的文本编辑器） |
| 写法 | `.string "第一行\n第二行$"`（`$` 结尾、`\n` 换行、`\p` 翻页） |
| 连锁 | 无 |
| 验证 | `make` → 游戏内对话 |
| 坑 | 单行太长会超框；`charmap.txt` 里没有的字编不过 |

```asm
MyTown_Text_Hello:
	.string "你好！\n今天天气不错。$"
```

### 场景 2：加一个 NPC

| 项 | 内容 |
|---|---|
| 改哪里 | ① `data/maps/<Map>/map.json` 的 `object_events` 数组<br>② 同目录 `scripts.inc` 写脚本 |
| 软件 | Porymap（可视化摆人）或 VS Code（手写 JSON） |
| 连锁 | `local_id` → 自动生成 `LOCALID_*` 常量（`include/constants/map_event_ids.h`，勿手改） |
| 验证 | `make` → 进图看人是否出现、对话是否触发 |

```json
{
  "local_id": "LOCALID_MY_TOWN_GIRL",
  "graphics_id": "OBJ_EVENT_GFX_GIRL_1",
  "x": 10, "y": 6, "elevation": 3,
  "movement_type": "MOVEMENT_TYPE_WANDER_AROUND",
  "movement_range_x": 1, "movement_range_y": 1,
  "trainer_type": "TRAINER_TYPE_NONE",
  "trainer_sight_or_berry_tree_id": "0",
  "script": "MyTown_EventScript_Girl",
  "flag": "0"
}
```

```asm
MyTown_EventScript_Girl::
	lock
	faceplayer
	msgbox MyTown_Text_Hello, MSGBOX_DEFAULT
	release
	end
```

> `graphics_id` 可选值在 `include/constants/event_objects.h`（`OBJ_EVENT_GFX_*`）。想加**全新外观**还要动 `graphics/object_events/pics/**` + `src/data/object_events/object_event_graphics_info*.h`，这属于场景 10。

### 场景 3：新建一张地图

| 项 | 内容 |
|---|---|
| 改哪里 | ① `data/layouts/<Layout>/`（`map.bin` + `border.bin`）<br>② `data/layouts/layouts.json` 登记布局<br>③ `data/maps/<Map>/map.json` 建地图<br>④ `data/maps/map_groups.json` 登记到分组 |
| 软件 | **Porymap**（新建地图向导会一次做完这 4 步） |
| 连锁 | `mapjson` 自动生成 `MAP_*` / `LAYOUT_*` 常量、`map_groups.h`、`map_group_count.h` |
| 验证 | `make` → 用 `warp MAP_NEW, 0, x, y` 或调试菜单跳过去 |

手写要点（`layouts.json` 一条）：

```json
{
  "id": "LAYOUT_MY_TOWN",
  "name": "MyTown_Layout",
  "width": 20, "height": 20,
  "primary_tileset": "gTileset_General",
  "secondary_tileset": "gTileset_Petalburg",
  "border_filepath": "data/layouts/MyTown/border.bin",
  "blockdata_filepath": "data/layouts/MyTown/map.bin",
  "layout_version": "emerald"
}
```

> `map.bin` 是**二进制**图块索引（每格 2 字节），**不要手改**。要用 Porymap 或自写脚本生成。

### 场景 6：加一个道具

| 项 | 内容 |
|---|---|
| 改哪里 | ① `include/constants/items.h`（常量，注意插入位置会影响现有 ID）<br>② `src/data/items.h`（数据条目）<br>③ `src/data/graphics/items.h`（图标声明）<br>④ `graphics/items/icons/<name>.png`（图 + 调色板） |
| 软件 | VS Code + Aseprite |
| 连锁 | 图标用 `INCGFX_U32("graphics/items/icons/xxx.png", ".4bpp.smol")` 声明；若有效果，还要在 `src/item.c` 写 `ItemUseOutOfBattle_*` |
| 验证 | `make` → 脚本 `giveitem ITEM_NEW` 拿到 |

```c
// include/constants/items.h
ITEM_MY_ORB = 800,

// src/data/items.h
    [ITEM_MY_ORB] =
    {
        .name = ITEM_NAME("神秘宝珠"),
        .price = 0,
        .description = COMPOUND_STRING(
			"散发着微光的神秘宝珠。\n"
			"用途不明。"),
        .pocket = POCKET_ITEMS,
        .type = ITEM_USE_BAG_MENU,
        .fieldUseFunc = NULL,
        .battleUsage = 0,
        .effect = NULL,
        .flingPower = 30,
        .iconPic = gItemIcon_MyOrb,
        .iconPalette = gItemIconPalette_MyOrb,
    },
```

### 场景 7：加一个招式

| 项 | 内容 |
|---|---|
| 改哪里 | ① `include/constants/moves.h`<br>② `src/data/moves_info.h`（名字/威力/命中/PP/效果）<br>③ 若新机制：`include/constants/battle_move_effects.h` + `src/data/battle_move_effects.h` + `data/battle_scripts_1.s`<br>④ 动画：`data/battle_anim_scripts.s` + `graphics/battle_anims/sprites/`<br>⑤ 华丽大赛：`src/data/contest_moves.h` |
| 软件 | VS Code + Aseprite |
| 连锁 | 学习表要能学到它 → `src/data/pokemon/level_up_learnsets/`、`src/data/pokemon/special_movesets.json`、`include/constants/tms_hms.h` |
| 验证 | `make` → 调试菜单给宝可梦学这招 |
| 教程 | `docs/tutorials/how_to_new_move.md` |

```c
// src/data/moves_info.h
    [MOVE_MY_BEAM] =
    {
        .name = COMPOUND_STRING("微光光束"),
        .description = COMPOUND_STRING(
			"放出微光攻击对手。\n"
			"有时会降低对手特防。"),
        .effect = EFFECT_HIT,
        .power = 80,
        .type = TYPE_FAIRY,
        .accuracy = 100,
        .pp = 15,
        .target = TARGET_SELECTED,
        .priority = 0,
        .category = DAMAGE_CATEGORY_SPECIAL,
        .additionalEffects = ADDITIONAL_EFFECTS({
            .moveEffect = MOVE_EFFECT_STAT_MINUS,
            .spDef = 1,                       // 降 1 级特防
            .chance = 30,
        }),
        .contestEffect = CONTEST_EFFECT_HIGHLY_APPEALING,
        .contestCategory = CONTEST_CATEGORY_BEAUTY,
        .battleAnimScript = gBattleAnimMove_MyBeam,   // 必须指向一个动画脚本，见 data/battle_anim_scripts.s
    },
```

> 别照抄"假常量"：追加效果统一走 `MOVE_EFFECT_STAT_MINUS` + `.attack/.defense/.speed/.spAtk/.spDef/.accuracy/.evasion` 字段（本项目 1.17 的写法，定义在 `include/constants/battle_set_effect.h`），没有 `MOVE_EFFECT_SP_DEF_MINUS_1` 这种东西。抄之前先 `grep MOVE_EFFECT_ src/data/moves_info.h` 看现有的真实用法。

### 场景 9：改机制（先想清楚改哪一层）

优先级从高到低：

```
include/config/*.h（改宏，最安全）
   ↓ 不够
src/data/*.h（改数据表）
   ↓ 不够
data/battle_scripts_1.s（改结算顺序/文字）
   ↓ 不够
src/*.c（改实现，风险最高）
```

例：想让"捕获也获得经验"

```c
// include/config/battle.h
#define B_EXP_CATCH GEN_LATEST     // Gen6+ 行为
```

例：想让全局回到第三代规则

```c
// include/config/general.h 里 GEN_LATEST 定义在 expansions 常量表
// 更稳的做法：把 include/config/pokemon.h 里所有 P_* 从 GEN_LATEST 改成 GEN_3
//            include/config/battle.h 里所有 B_* 同理
```

改完必须 `make clean && make`——配置宏被几百个 `.c` 包含，增量编译靠不住。

### 场景 10：换/加图片

| 类型 | 目录 | 规格 | 注意 |
|---|---|---|---|
| 宝可梦正面/背面 | `graphics/pokemon/<name>/` | 64×64，索引色 ≤16 色，PNG | 编译成 `.4bpp.lz` |
| 图标 | 同上 `icon.png` | 32×64（两帧） | `.4bpp` |
| 训练家立绘 | `graphics/trainers/front_pics/` `back_pics/` `palettes/` | 64×64 | 新图需在 `src/data/graphics/trainers.h` 声明 |
| 道具图标 | `graphics/items/icons/` | 24×24 | 调色板 ≤16 色 |
| NPC 行走图 | `graphics/object_events/pics/**` | 16×32 单帧，整表 2×4 帧 | 由 `spritesheet_rules.mk` 切 |
| UI 界面 | `graphics/interface/` 等 | 视界面而定 | 改完看 `.map` 文件是否超容量 |
| 地图图块 | `data/tilesets/` + `graphics/tilesets/` | 8×8 图块 | 必须配套 `metatile` 属性 |

**索引色是硬约束**：Aseprite 里 `Sprite → Color Mode → Indexed`，调色板超 16 色就要减色（`gbagfx` 会直接报错或颜色错乱）。

### 场景 11：加一首 BGM

| 步骤 | 操作 |
|---|---|
| 1 | 放进 `sound/songs/midi/mus_mytown.mid` |
| 2 | `sound/songs/midi/midi.cfg` 加一行：`mus_mytown.mid: -E -R50 -G_mytown -V080` |
| 3 | `sound/song_table.inc` 注册 `song mus_mytown, MUSIC_PLAYER_BGM, 0` |
| 4 | `include/constants/songs.h` 加 `MUS_MY_TOWN` |
| 5 | 脚本里 `playbgm MUS_MY_TOWN, TRUE` |
| 6 | `make`（`mid2agb` 会自动转成 `.s`） |

> MIDI 限制：最多 5 条旋律轨 + 1 鼓轨；音色必须在 `sound/voicegroups/` 里有对应。用原版没有的乐器会静音。

### 场景 12：删除内容（危险，按顺序来）

**通用四步法**：

```bash
# 1) 先查所有引用（以删一只宝可梦为例）
grep -rn "SPECIES_MY_MON" src include data test --include=*.c --include=*.h --include=*.inc --include=*.json

# 2) 先删"引用"（脚本、分布、队伍、测试）
# 3) 再删"定义"（constants、species_info、graphics、cries）
# 4) make 编译验证 + 游戏内跑一遍
```

各类型的引用排查命令：

| 删什么 | 排查命令 |
|---|---|
| 宝可梦 | `grep -rn "SPECIES_X" src include data test` |
| 招式 | `grep -rn "MOVE_X" src include data test` |
| 道具 | `grep -rn "ITEM_X" src include data test` |
| 特性 | `grep -rn "ABILITY_X" src include data test` |
| 训练家 | `grep -rn "TRAINER_X" src include data test` |
| 地图 | `grep -rn "MAP_X" src include data` + 删 `data/maps/X/` + `map_groups.json` 条目 |
| 标签/变量 | `grep -rn "FLAG_X\|VAR_X" src include data` |

**删地图的完整链条**（5 处）：

1. 删目录 `data/maps/<Map>/`（含 `map.json`、`scripts.inc`）
2. `data/maps/map_groups.json` 里删该地图的名字
3. 删 `data/layouts/<Layout>/`（若独占布局）
4. `data/layouts/layouts.json` 里删该布局
5. `grep MAP_<MAP>` 清掉所有 `warp` / `setrespawn` / 事件引用

`dev_scripts/delete_frlg_maps.py` 就是干这件事的现成脚本（针对 FRLG 地图集），可以参考它的实现写自己的批量删除。

**删完必须**：`make clean && make`（旧的目标文件可能还引用已删符号）。

## 5. 变更影响矩阵（改完要等多久）

| 改动位置 | 重新编译范围 | 大致耗时 | 是否需要 `make clean` |
|---|---|---|---|
| `data/maps/*/scripts.inc` | 该地图事件数据 + 链接 | 10–60 秒 | 否 |
| `data/battle_scripts_1.s` | `battle_scripts_1.o` + 链接 | 30–60 秒 | 否 |
| `src/*.c` 单个文件 | 该 `.o` + 链接 | 5–20 秒 | 否 |
| `src/data/*.h` | 引用它的 `.o`（常含 `data.o`） | 1–3 分钟 | 否 |
| `graphics/**/*.png` | 该图片转换 + 链接 | 秒级 | 否 |
| `include/config/*.h` | **几乎所有 `.c`** | 10–20 分钟 | **是** |
| `include/constants/*.h` | 大部分 `.c` | 3–15 分钟 | 建议 |
| 新增 `.c` 文件 | 只需 `make`（Makefile 用 wildcard 自动收集） | 视情况 | 否 |
| `ld_script_modern.ld` | 全量链接 | 1 分钟 | 建议 |

> 所以：**先改脚本和数据（秒级迭代），最后再动 config**。调数值时不要碰 `include/config/`，否则每次改完等 15 分钟。

## 8. 与上游同步（fork 的必修课）

```bash
git remote -v                       # origin=你的 fork，upstream=rh-hideout-chinese
git fetch upstream
git checkout master
git merge upstream/master           # 冲突多时用 rebase，但 rebase 已推送的分支要 force push
```

合并后必做：

1. 读 `docs/CHANGELOG.md` 对应版本条目（哪些 API 改了）
2. 看 `migration_scripts/<新版本>/README.md`，按需跑迁移脚本
3. `make clean && make`（合并后旧 `.o` 不可信）
4. `make check`

**你的改动和上游冲突时**：优先保留上游重构，把自己的改动重写到新结构上。硬顶冲突（保留自己的旧实现）等于自断升级路径。

## 9. 12 个高频踩坑

| # | 坑 | 表现 | 修法 |
|---|---|---|---|
| 1 | 用了空格缩进 | 汇编报 `unexpected token` | 改 Tab |
| 2 | 文本没写 `$` | 对话跑到下一段文本 | 补 `$` |
| 3 | `lock` 没配 `release` | 玩家永久卡住 | 成对写 |
| 4 | 手改了生成文件 | 下次 `make` 改动消失 | 改输入（json/party/inc） |
| 5 | 在 `items.h` 中间插道具 | 旧存档道具全错位 | 加末尾 + 显式赋值 |
| 6 | 中文里有 `charmap.txt` 没收录的字 | `unknown character` 编译失败 | 补映射或换字 |
| 7 | 改了 `include/config/*.h` 只做增量编译 | 行为不一致、诡异 bug | `make clean && make` |
| 8 | PNG 不是索引色 / 超过 16 色 | `gbagfx` 报错或颜色错乱 | Aseprite 转 Indexed |
| 9 | `map.json` 少逗号 | `mapjson` 解析失败 | VS Code JSON 校验 |
| 10 | 删了地图没清 `map_groups.json` | 链接期 `undefined reference` | 按第 4.12 节五步删 |
| 11 | 把 `build/` 或 `.gba` 提交了 | 仓库暴涨 | `git rm -r --cached build`，`.gitignore` 已覆盖 |
| 12 | 用 ZIP 下载而非 clone | `check_history.sh` 拦编译 | `touch .histignore` 或改 clone |

## 10. 一次完整改动示例（送礼 NPC，端到端）

```bash
git checkout -b content/gift-npc
```

**① 加常量（可选，用旗标防重复）**

`include/constants/flags.h`：

```c
#define FLAG_RECEIVED_MY_TOWN_GIFT  0x2A0   // 选一个未占用的编号
```

**② 加 NPC（`data/maps/MyTown/map.json`）** → 见场景 2

**③ 加脚本（`data/maps/MyTown/scripts.inc`）**

```asm
MyTown_EventScript_GiftGirl::
	lock
	faceplayer
	goto_if_set FLAG_RECEIVED_MY_TOWN_GIFT, MyTown_EventScript_GiftDone
	giveitem ITEM_POTION, 3
	goto_if_eq VAR_RESULT, FALSE, Common_EventScript_ShowBagIsFull
	setflag FLAG_RECEIVED_MY_TOWN_GIFT
	msgbox MyTown_Text_GiftThanks, MSGBOX_DEFAULT
	release
	end

MyTown_EventScript_GiftDone::
	msgbox MyTown_Text_GiftAlready, MSGBOX_DEFAULT
	release
	end

MyTown_Text_GiftThanks:
	.string "这个给你，路上小心！$"

MyTown_Text_GiftAlready:
	.string "药已经给过你啦。$"
```

**④ 编译 + 验证**

```bash
make -j"$(nproc)" -O
# mGBA 打开 pokeemerald.gba → 标题按 SELECT 快速开局 → 走到 NPC 前
```

**⑤ 提交**

```bash
git add data/maps/MyTown/map.json data/maps/MyTown/scripts.inc include/constants/flags.h
git commit -m "content: add gift NPC in MyTown"
git push -u origin content/gift-npc
```
