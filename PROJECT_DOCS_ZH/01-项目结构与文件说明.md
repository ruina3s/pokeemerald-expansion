# 01 项目结构与文件说明

> 结论先行：这是 **pret/pokeemerald 的反编译工程 + RHH pokeemerald-expansion 1.17.3 扩展**，并且是 **rh-hideout-chinese 中文汉化分支**（游戏内文本已是中文）。它不是一个"引擎"，而是一套**把 C 源码 / 汇编脚本 / PNG 图片 / MIDI 音乐 编译成 GBA ROM 的构建系统 + 数据表**。
>
> 所以定位一个改动点的原则只有一条：**先判断它是"数据"还是"逻辑"**。
> - 数据（数值、文本、地图、队伍、掉落、分布）→ `src/data/`、`data/`、`graphics/`、`sound/`
> - 逻辑（招式机制、AI、菜单、战斗流程）→ `src/*.c` + `include/*.h`
> - 开关（代际平衡、特性开关）→ `include/config/*.h`（**改这里最省事**）

- 你的仓库：<https://github.com/ruina3s/pokeemerald-expansion>（fork，public，默认分支 `master`）
- 上游 fork：<https://github.com/rh-hideout-chinese/pokeemerald-expansion>
- 原始扩展上游：<https://github.com/rh-hideout/pokeemerald-expansion>
- 反编译母项目：<https://github.com/pret/pokeemerald>

## 4. 逐目录详解

### 4.1 `src/` —— 全部 C 逻辑（385 个 `.c`）

按职能分组，这是"改机制"唯一要去的地方：

| 分组 | 代表文件 | 说明 |
|---|---|---|
| 战斗流程 | `battle_main.c` `battle_script_commands.c` `battle_util.c` `battle_end_turn.c` `battle_move_resolution.c` | 战斗主循环、脚本指令实现、伤害/命中/类型计算 |
| 战斗 AI | `battle_ai_main.c` `battle_ai_util.c` `battle_ai_switch.c` `battle_ai_items.c` | 对手/搭档 AI 决策与评分 |
| 战斗外围 | `battle_controller_*.c`（12 个）`battle_anim*.c`（30+）`battle_dynamax.c` `battle_gimmick.c` | 控制器（玩家/对手/录像）、招式动画、极巨化与机制 |
| 战斗设施 | `battle_tower.c` `battle_dome.c` `battle_pike.c` `battle_pyramid.c` `battle_factory.c` `battle_arena.c` `battle_palace.c` | 对战开拓区各设施规则 |
| 宝可梦 | `pokemon.c` `pokedex.c` `pokedex_plus_hgss.c` `party_menu.c` `summary_screen.c` `move_relearner.c` `daycare.c` | 个体数据、图鉴、队伍菜单、回忆技能、饲养屋 |
| 野外/大地图 | `wild_encounter.c` `overworld.c` `field_*.c`（20+）`follower_npc.c` `dexnav.c` `mass_outbreak.c` | 遇敌、走图、野外招、跟随 NPC、图鉴导航、大量发生 |
| 战斗外系统 | `item.c` `shop.c` `script.c` `scrcmd.c` `event_object_movement.c` | 道具使用、商店、事件脚本解释器、对象移动 |
| 界面 | `menu.c` `main_menu.c` `option_menu.c` `bag.c` `trainer_card.c` `pokenav*.c` `pokemon_storage_system.c` | 各类菜单与 UI |
| 数据表（C 数组） | `src/data/*.h` 866 个条目（见 4.3） | 招式、道具、特性、训练家、分布… |
| 调试 | `battle_debug.c` `debug.c` `pokemon_sprite_visualizer.c` | 游戏内调试菜单（**默认编出来就带**，`make release` 才会关；开关在 `include/config/debug.h`） |
| 测试框架 | `test_runner.c` `test_runner_args.c` `test_runner_stubs.c` | 在 ROM 内运行测试 |

> 注意：`src/*.inc.c` 是被其他 `.c` `#include` 的片段，Makefile 明确把它们从独立编译列表中排除（`$(if $(findstring .inc.c,$(src)),,...)`）。

### 4.2 `include/` —— 接口与常量（315 个头文件）

```
include/
├── config/     (23)   ← 特性开关，改游戏行为的"控制面板"
├── constants/  (120)  ← 枚举/数值：招式、道具、特性、地图、旗标、变量…
├── gba/        (10)   ← GBA 硬件寄存器与 BIOS 声明

```

**`include/config/` 是性价比最高的目录**——这里的宏直接切换机制，不用写一行逻辑：

| 文件 | 管什么 |
|---|---|
| `general.h` | 代际基准 `GEN_LATEST`、BUGFIX/UBFIX、日志、单位制、键盘大小写 |
| `battle.h` | 345 个 `B_*`：经验、捕获、状态、暴击、极巨化、Mega、Z 招式、AI 难度… |
| `pokemon.h` | `P_*`：种族值/属性/特性更新、孵蛋规则、性别差异、学习表 |
| `item.h` | `I_*`：道具价格、背包、TM 规则、携带效果 |
| `ai.h` | AI 评分参数与开关 |
| `wild_encounter.h` | 遇敌机制、图鉴导航遇敌、时间遇敌 |
| `overworld.h`、`fishing.h`、`pokerus.h`、`save.h`、`text.h`、`test.h`、`quickstart.h`… | 各自系统的开关 |
| `debug.h` | 三个游戏内调试菜单（大地图 `R+START` / 战斗 `SELECT` / 能力页 `SELECT`），默认全开，`make release` 全关 |

> `GEN_LATEST` = Gen 9。把所有 `P_*` 设成 `GEN_3` 就得到"纯第三代手感"。

**一个地图目录（例：`data/maps/LittlerootTown/`）**

| 文件 | 谁生成 | 作用 |
|---|---|---|
| `map.json` | **人写** | 地图元数据：音乐、天气、连接、对象事件、传送点、坐标触发器、背景事件 |
| `scripts.inc` | **人写** | 该地图的事件脚本（`Label::` + 宏）与文本 |
| `header.inc` `events.inc` `connections.inc` | `mapjson` 生成 | 编译产物，**不要手改** |

**格式规则（踩坑重点）**

- 必须是**索引色 PNG**，调色板 ≤ 16 色（`.gbapal` 一色 2 字节，16 色 = 32 字节）
- 生成物 `.4bpp/.8bpp/.1bpp/.gbapal/.lz/.smol` **全部由 `gbagfx` 编译产生，不进 git**（`.gitignore` 已忽略）
- 改图后必须 push 让 CI 重新转换，否则下载到的 ROM 里还是旧图

### 4.13 根目录构建文件的职责

| 文件 | 何时被读 | 关键点 |
|---|---|---|
| `Makefile` | 每次编译 | 决定 `GAME_VERSION`、编译标志、链接脚本；`make` 前会先跑 `make tools` 和 `make generated` |

| `rom.sha1` | `make compare` | 只有 `COMPARE=1` 才用到，且需要原版 `baserom.gba` |

## 5. 编译流水线（数据怎么变成 ROM）

> **编译口径：全部在 GitHub Actions 上跑，本机不装工具链。**
> 下图描述的是 `.github/workflows/build-rom.yml` 在 runner 内部完成的动作。
> 你在本机要做的只有：改文件 → `git push` → 页面上等绿色对勾 → 下载 Artifacts → mGBA 打开验证。
> 完整配置见 `02-GitHub-Actions线上编译.md`，日常流程见 `04-修改项目工作流.md`。

```
PNG/PAL ──gbagfx──► .4bpp/.gbapal/.lz/.smol ─┐
MIDI    ──mid2agb─► .s（M4A 汇编）───────────┤
WAV     ──wav2agb─► .bin ────────────────────┤
map.json──mapjson─► header/events/conn .inc ─┤
*.json  ──jsonproc► *.h ─────────────────────┤
*.party ─trainerproc► *.h ───────────────────┤
                                             ▼
.c/.s ──cpp──► preproc(incl. charmap) ──► cc1 ──► as ──► .o
                                                            │
                                              ld (ld_script_modern.ld)
                                                            ▼
                                            pokeemerald.elf ──gbafix/objcopy──► pokeemerald.gba
```

关键点：

1. **C 文件不是直接编译的**：`cpp` 预处理 → `preproc`（处理 `#` 与中文编码）→ `cc1` → `as`。所以**中文可以写在 C 字符串里**，靠 `charmap.txt` 转字节。
2. **每次 `make` 会先编译工具 + 生成数据**（`SETUP_PREREQS=1`）。在 CI 里表现为：先编 14 个工具（有缓存则秒过）→ 转 1.1 万张 PNG → 生成各 `.h` → 才编 385 个 `.c`。这就是"首次 15–22 分钟、有缓存 8–12 分钟"的由来。
3. **依赖追踪靠 `scaninc`** 生成的 `.d` 文件。CI 每次是干净检出，没有历史 `.d`，所以**每次都是接近全量**——这也是线上编译耗时与"改了多少"几乎无关的原因。
4. `.DELETE_ON_ERROR`：编译失败会删掉半成品，避免"用旧产物骗过增量编译"。

## 6. "我要改 X，去哪"速查表

| 需求 | 主要文件 | 辅助文件 |
|---|---|---|
| 改某地图的对话 | `data/maps/<Map>/scripts.inc` | `data/maps/<Map>/map.json`（触发器绑定） |
| 加一个 NPC | `data/maps/<Map>/map.json` → `object_events` | 同目录 `scripts.inc` 写脚本 |
| 改野生分布 | `src/data/wild_encounters.json` | `include/config/wild_encounter.h` |
| 加/改训练家队伍 | `src/data/trainers.party` | `include/constants/opponents.h`（`TRAINER_*` 常量） |
| 改招式数值 | `src/data/moves_info.h` | — |
| 改招式的效果逻辑 | `data/battle_scripts_1.s` + `src/battle_script_commands.c` | `src/data/battle_move_effects.h` |
| 改道具 | `src/data/items.h` | `include/constants/items.h`、`graphics/items/` |
| 改宝可梦种族值 | `src/data/pokemon/species_info/gen_*_families.h` | `graphics/pokemon/` |
| 改学习表 | `src/data/pokemon/level_up_learnsets/gen_*_families.h` | — |
| 改 UI/菜单 | `src/<模块>.c` + `graphics/<模块>/` | `include/<模块>.h` |
| 调平衡（代际手感） | `include/config/*.h` | — |
| 加音乐 | `sound/songs/midi/*.mid` + `midi.cfg` + `song_table.inc` + `constants/songs.h` | — |
| 加地图 | `data/maps/<新目录>/map.json` + `data/layouts/<新目录>/` | `map_groups.json`、`layouts.json` |
| 加对话文本（中文） | 对应 `scripts.inc` 的 `Text_xxx:` 段 | `charmap.txt` 里有该字才能显示 |

## 7. 一句话总结结构逻辑

**`data/` 装"世界"（地图、脚本），`src/data/` 装"规则数据"（招式、种族、道具），`src/` 装"规则实现"（引擎），`include/config/` 装"规则开关"，`graphics/`+`sound/` 装"表现"，`tools/`+`*.mk` 装"怎么把前面这些变成 ROM"。**
